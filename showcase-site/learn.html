Learn the loop

Three short lessons. Switch Edit and Preview in the app as you go — this page is meant to be opened in werkstatt.

Lessons

Open a folder, not a project file

werkstatt loads a directory. Home is index.html. Styles come from the first local stylesheet link — here, styles.css.

  • Use Open site folder, or drop the folder on the welcome screen.
  • Stay in Edit to select elements. Preview runs app.js.
  • Try the tablet and mobile widths. This site’s breakpoints are 768 and 375.

The panel is the stylesheet

Click the title on this page. You should land on .hero-title. Change size, color, or a token — the rule is shared with every page that uses the class.

  • Prefer class rules over inline styles. The panel cannot follow a style="".
  • Brand values live in :root. Night values live on [data-theme="dark"].
  • To style an open menu, target .site-nav.is-open — do not wait for the script.

Save, then tell the next run

Save writes the HTML and CSS you see. If an agent will run again, copy a handoff note so your word changes and spacing tweaks are not treated as drift.

  • Keep class names, token names and file paths stable.
  • Read AGENT_HANDOFF.md on the next agent pass if it exists.
  • Run Site check after a generation: missing alts, dead links, classes with no rule.

Questions from the bench

Closed in the HTML so Edit mode shows the resting state. Open one in Preview, or simulate .is-open.

Edit has to keep the DOM still. A slider that wraps your markup, or a script that injects the hero, would hide the source you came to change. Preview is the throwaway run.

In one :root block, named so you can find them: --plum, --ink, --violet, --space-lg. Then use var() from the classes.

Write it down. The handoff note lists text, classes and styles you changed since the last save. The next run is asked to keep those, and not rename the classes they hang on.

Then break things on purpose.
